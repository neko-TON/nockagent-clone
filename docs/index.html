Introduction

None documentation

None turns a sentence into a settled trade. You describe an outcome in plain language; the engine quotes every venue on Robinhood Chain, picks the path with the best net output, and hands your wallet a single transaction to sign.

Three properties hold throughout the system, and the rest of this document is mostly consequences of them:

  • Non-custodial. Funds never leave your wallet. There is no deposit step and no omnibus account.
  • Quoted from chain state. Every number shown comes from the on-chain quoter at a specific block, not from a cache or an estimate.
  • Fails closed. Every trade carries a minimum-out and a deadline. Adverse movement reverts rather than fills badly.

Chain

Robinhood Chain — an Arbitrum L2, EVM-equivalent. Block time ~250ms, sub-second finality.

Venues

Uniswap v2, v3 (0.01% / 0.05% / 0.30% / 1.00%) and v4 pools, quoted in parallel.

Base assets

USDG and WETH carry the deepest liquidity and act as intermediate hops.

Assets

Tokenized equities (24/5) alongside crypto (24/7), routed by the same engine.

Quickstart

From zero to a signed trade

  1. Connect a wallet. Any standard EVM wallet that can sign on Robinhood Chain. One click, no account, no email.
  2. State the outcome. Type what you want — Buy $5,000 of NVDA. No pool selector, no fee tier, no calldata.
  3. Read the plan. None shows the route, the expected rate, price impact and the minimum you will receive.
  4. Sign once. The optimized swap settles in a single transaction from your own wallet.

Try it without funds in the interactive simulator — it runs the same intent parser and quoting model against simulated liquidity.

Intent language

What you can type

The parser resolves four things: the side, the amount, the input asset and the output asset. Anything that pins those down is valid input — you do not need a fixed syntax.

You typeParsed as
Buy $5,000 of NVDAspend 5,000 USDG → receive NVDA
Swap 2 ETH into COINspend 2 WETH → receive COIN
Get me $3,000 of AMZNspend 3,000 USDG → receive AMZN
Sell my AAPLspend full AAPL balance → receive USDG
Swap half my USDG into TSLAspend 50% of USDG balance → receive TSLA
Ambiguity is surfaced, not guessed. If an instruction resolves to more than one plausible trade, None asks rather than picking for you. It will not invent a size you did not state.
Routing engine

How a route is chosen

Quoting runs as a fan-out, not a sequence. Each candidate path is priced against live chain state, then scored on net output — gross output minus pool fees minus gas.

# candidate set for: buy NVDA with 5,000 USDG
USDG → NVDA            // v3 0.05%   direct
USDG → NVDA            // v3 0.30%   direct
USDG → WETH → NVDA     // v3 + v3    2 hops
USDG → WETH → NVDA     // v2 + v3    2 hops
USDG → USDC → NVDA     // v3 0.01%   2 hops

winner  USDG → WETH → NVDA   net out 12.63 NVDA
naive   USDG → NVDA          net out 12.41 NVDA
delta   +0.22 NVDA (+1.77%)
  • Depth: up to three hops. Deeper paths rarely survive gas scoring on an L2 this cheap, but they are evaluated.
  • Refresh: quotes re-run on every keystroke and every block (~250ms), so the displayed rate tracks the market.
  • Honesty: if no path exists or a pool is dry, the engine returns nothing and says so. It never synthesizes a price.
Execution guards

What protects the fill

GuardDefaultEffect
Minimum outquote − slippage toleranceTransaction reverts if output would fall below it.
Slippage tolerance0.50%User-adjustable per trade; tightened automatically on deep liquidity.
Deadline120sA pending transaction cannot execute at a stale price later.
Pre-flight simulationalwaysThe winning path is simulated before a signature is requested.
Reverts are a feature. A reverted trade costs gas and returns your funds. A filled-at-any-price trade costs the spread. None is built to prefer the first.
Agent API · x402

Machine callers pay per request

The best-route engine is exposed as an HTTP endpoint priced with HTTP 402 Payment Required. A calling agent requests a quote, receives a payment challenge, signs a stablecoin authorization, and repeats the call with the payment header. No account, no API key handshake, no card.

$ curl -i https://none.app/api/agent?from=WETH&to=USDG&amount=1

HTTP/1.1 402 Payment Required
{
  "accepts": [
    { "scheme": "exact", "asset": "USDG", "price": "0.01", "network": "robinhood" }
  ],
  "expires": 1785312000
}

$ curl -s -X POST https://none.app/api/agent \
    -H "X-PAYMENT: <signed-authorization>" \
    -d '{"from":"WETH","to":"USDG","amount":"1"}'

HTTP/1.1 200 OK   · paid ✓
{
  "rate":  "1 ETH ≈ 1,831 USDG",
  "route": ["WETH","USDG"],
  "venue": "uniswap-v3",
  "fee":   "0.05%",
  "netOut":"1831.42",
  "block": 48210233
}

Payment settles in USDG on Robinhood Chain. Pricing is per successful call; 402 challenges are free.

Safety model

Why custody is not a promise here

  • No deposits. There is no address to send funds to, so there is no balance for anyone to lose or freeze.
  • Scoped approvals. Permit2 allowances are bounded by amount and expiry rather than unlimited and permanent.
  • No privileged role. There is no admin key that can move user funds, because user funds are never held by the protocol.
  • Deterministic failure. Minimum-out plus deadline means the worst case is a reverted transaction and a gas cost.
What None cannot protect you from: signing a malicious transaction in another tab, a compromised wallet or device, or a decision to trade an asset you have not researched. Custody of keys means custody of consequences.
Glossary

Terms used here

Best execution
The path producing the largest output after pool fees and gas — not the one with the headline rate.
Minimum out
The floor on what you receive. The transaction reverts below it.
Multi-hop
A route through one or more intermediate assets, usually WETH or USDG, when it beats the direct pair.
Naive swap
The direct single-pool trade a user would most likely click by hand — the baseline None compares against.
Price impact
How much your own size moves the pool price. Large relative to depth means a worse fill.
Slippage tolerance
How far the price may move against you before the transaction reverts.
x402
An HTTP payment flow using status 402, letting machines pay per request in stablecoin without an account.
Tokenized equity
An on-chain instrument tracking a listed stock, trading against crypto liquidity during market hours.
